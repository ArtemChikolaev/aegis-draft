# Aegis Arcade — 2D survivors-роглайк по Dota
## Бриф по референсу Death Must Die: что это, ложится ли на наш стек и как это перевести на язык Dota

**Дата:** 2026-09-05
**Статус:** исследование + предложение. Продуктовое решение — [PRD §5.15](PRD.md), декомпозиция — [BACKLOG M13](BACKLOG.md). Кода нет.
**Назначение:** ответить на вопрос владельца «реально ли сделать аналог Death Must Die с героями Dota отдельным режимом» и, если да, дать точку входа для разработки.

## 0. Вердикт коротко

- **Реально — как ограниченный вертикальный срез, не как клон.** Death Must Die (DMD) — двухлетний Early Access студии с пиксель-артом, анимированными героями, сотнями благословений и предметами с аффиксами. Наш стек (TS + React + Vite, static-first, PWA) выдерживает жанр «bullet heaven» технически, но **жанр другой**: это real-time симуляция 60 Гц с сотнями сущностей, а всё, что у нас есть сейчас, — пошаговый симулятор турнира поверх DOM.
- **Что переиспользуем (много):** шелл режимов и сторы, карьеру/Штаб, сиды и `Rng`, i18n/токены/`ui/`, звук R15.5, PWA-офлайн, 127 портретов героев и 34 иконки предметов, словарь редкостей/изданий предметов, методику headless-симулятора для баланса (`npm run sim`).
- **Что придётся писать с нуля:** игровое ядро (тик, сущности, коллизии, снаряды, урон), рендер (Canvas/WebGL, не DOM), ввод (клавиатура/мышь/тач), контент (способности, школы, враги, боссы) и **арт в движении** — главный риск.
- **Рекомендация:** делать срез 0 (один герой, одна карта, 7 минут до Рошана) и принимать go/no-go по плейтесту «весело ли 5 минут». Полная DMD-parity — месяцы контента, её не планируем.

Каждый бог — свой статус-эффект и синергии между богами. |

## 2. Перевод на язык Dota (предложение)

Принцип тот же, что у Roguelite Run (PRD §5.10): берём **механику** референса, но каждая сущность должна читаться игроком Dota без объяснений.

| DMD | Aegis Arcade | Почему так |
|---|---|---|
| Герой с авто-атакой | **Герой Dota**: автоатака + Q/W/E/R. Срез 0 — Juggernaut (Blade Fury — «спин» как у survivors, Healing Ward — сустейн, Omnislash — ульт-«очистка экрана»). Дальше Crystal Maiden (морозная зона), Sniper (дальний бой), Axe (танк/таунт), Zeus (цепные молнии). | Кит героя уже знаком; портреты есть в `web/public/art/heroes`. |
| Уровень → благословение бога | **Уровень 1–25 как в Dota:** очки в Q/W/E, R на 6/12/18, **таланты на 10/15/20/25** (= DMD Passive). Сверху — **школы**. | Игрок Dota знает лестницу 6/12/18 и таланты наизусть. |
| Боги (макс. 3) | **Школы предметов (макс. 3 за забег)**, названы предметами-иконами: `Radiance` (горение), `Skadi` (заморозка), `Maelstrom` (цепная молния), `Bloodthorn` (кровотечение/rupture), `Basher` (стан), `Necronomicon` (призывы + проклятие), `Daedalus` (крит/удача = Moirai), `Satanic` (вампиризм = Justice), `Octarine` (КД/радиус сбора = Time). На уровне «продавец» школы предлагает 3 апгрейда типа Attack/Strike/Cast/Power/Summon/Passive/Dash. | Иконки уже в `web/public/art/items`, словарь редкостей `standard/refined/exotic/arcana` и изданий `Charged/Tempered` уже есть (`game/items.ts`, `game/editions.ts`). |
| Карта акта | **Акт 1 — лес Radiant днём**, акт 2 — лес Dire ночью (радиус обзора меньше), акт 3 — река и яма Рошана, финал — хайграунд и Древний. | Тематика ландшафта Dota; тайлы — плоская изометрия/топ-даун. |
| Миньоны | **Нейтралы по лагерям**: кобольды, тролли, сатиры, огры, кентавры, вайлдвинги, големы; «древние» лагеря (чёрные драконы, тандерхайды) как элита. **Крип-волны** каждые 30 с (лейн-крипы), осадные — каждая 5-я. | Читаемая эскалация силы ровно как в Dota. |
| Боссы 7:00 / 14:00 | **Рошан на 7:00 и 14:00**, второй сильнее (как респавн). Дроп — **Aegis (одно воскрешение)**, со второго — Cheese/Refresher Shard. Мини-босс между ними — **Tormentor**. | Aegis — название проекта; механика «второй шанс» — точь-в-точь смысл предмета. |
| Финал на 20:00 | **Древний**: на 20:00 таймер заканчивается, открывается хайграунд, нужно снести Древнего за 2 минуты под мегакрипами. | Цель забега формулируется одной фразой: «дожить и снести трон». |
| Алтари риска | **Руны щедрости/стаки**: активировал — ближайшие 60 с двойной спавн и дроп, множитель силы врагов +X% до конца забега. | Стак лагерей = каноническое «риск ради фарма». |
| Магазин, золото | **Золото за убийства и bounty-руны каждые 3 минуты; Secret Shop** появляется на карте в окна (3:00, 10:00, 17:00). Предметы — редкость × тир × 1–2 аффикса. **Нейтральные предметы** по минутам (тир 1 с 7:00 … тир 5 с 60:00 в Dota; у нас сжато до окна забега). | Тиры нейтралок = встроенная временная шкала силы лута. |
| Лестница сложности 0–40 | **Ранги Dota: Herald → Guardian → Crusader → Archon → Legend → Ancient → Divine → Immortal, по 5 звёзд** = 40 ступеней. Каждая ступень — конкретный модификатор (HP/скорость/плотность/новый тип элиты). | Один-в-один шкала DMD, но в терминах, которые игрок уже уважает. |
| Талант-дерево между забегами | **Штаб** (§5.10.1): вкладка Arcade — открытие героев и школ за осколки Aegis. **Без постоянных +статов** (принцип §5.10: честность сида и дейлика). | Совпадает с уже принятым правилом мета-прогрессии. |
| — (нет у DMD) | **Опционально позже:** «сигнатура про-игрока» — при выборе героя предлагается 1 из 3 топ-игроков на нём (по `playerHeroStats`), каждый даёт отличительный твист (например, Miracle- на Anti-Mage: Blink чаще, но меньше HP). | Единственное, чего нет ни у кого: наш датасет про-сцены. Не для среза 0. |

Рабочее название режима в шелле — **Arcade** (карточка «Аркада»); имя продукта (например, «Ancient Must Fall») — решение владельца.

## 3. Техническая осуществимость

### 3.1. Чего нет в проекте и что нужно

| Компонент | Сейчас | Нужно | Оценка |
|---|---|---|---|
| Игровой цикл | Пошаговый `RunEngine`/`TournamentEngine`, нет real-time | Фиксированный тик (60 Гц сим или 30 Гц + интерполяция), массивы сущностей (SoA), spatial hash для коллизий, снаряды, статусы, урон, XP-шарды, спавнер по расписанию | ядро ≈ 2–3 тыс. строк TS, без зависимостей |
| Рендер | React DOM | **DOM не тянет 300–800 спрайтов в 60 fps.** Canvas 2D (0 зависимостей, хватает на десктопе до ~500 сущностей) или PixiJS 8 (WebGL/WebGPU батчинг, ~400 КБ, лениво грузимый чанк) | рендер за интерфейсом; старт с Canvas 2D, Pixi — по профилю |
| Ввод | клики по карточкам | WASD/стрелки + мышь (прицел), геймпад, **виртуальный джойстик для тача** (Telegram Mini App §5.11 — сильный плюс режима) | 1–2 дня |
| Детерминизм | seed → паки/поле/матчи | Тот же принцип: `seed + input-лог {tick, dx, dy, actions}` ⇒ тот же забег. В симе избегаем `Math.sin/cos/exp` (реализации браузеров расходятся) — LUT или полиномы; никакого `Date.now`/rAF внутри сима | бесплатно, если заложить с первого дня; даёт реплей, шаринг и дейлик |
| Баланс | `npm run sim` с агентами | Headless-сим той же логики с бот-политикой (авто-кайт от центра масс врагов + сбор XP) → кривые выживаемости по герою/школе/рангу. `ARCADE_CONFIG_VERSION` отдельно от `BALANCE_CONFIG_VERSION` (другая PvE-модель) | переиспользуем методику 1-в-1 |
| Арт | 127 портретов, 34 иконки предметов, арт-зеркало в репо (ADR 0003) | **Анимированных спрайтов нет и брать их из клиента Dota нельзя.** Срез 0 — стиль «жетонов»: медальон-портрет + процедурные VFX (формы/частицы, токены цвета). Пиксель-спрайты — отдельное решение (заказ/генерация), только после go. | главный риск сроков и вкуса |
| Звук | слой R15.5 (короткие SFX) | Луп-музыка + ~20 SFX с пулом голосов | переиспользуем слой |
| Сейвы | `runPersist`, карьера local-first | Забег 20 минут **не сохраняется посреди тика** (как у DMD); пауза по `visibilitychange`; в карьеру пишется результат (`mode: "arcade"`) | без новых схем |
| Данные | `heroes.json` (`id/name/picture`), `items.ts` | Контент режима (способности, школы, враги, расписание волн) — **TS-контент в `game/arcade/content/`**, не JSON-схема: пайплайна за ним нет. Схема появится, если контент вынесем в данные. | без правки `schema/` в срезе 0 |
| Сервер | ADR 0002: анти-чит ре-симуляцией на Go | Портировать real-time сим на Go — нет. Дейлик Arcade — local-first (как §5.14); серверный лидерборд — открытый вопрос (ре-сим лога в Node/WASM на сервере или доверие клиенту) | не блокирует |

### 3.2. Производительность — реалистичный потолок в браузере

- Canvas 2D: 500 спрайтов + 300 снарядов при 60 fps на десктопе — норма; на среднем Android — 200–300. Этого хватает для акта 1 (у DMD плотность акта 1 ~150–300 врагов на экране).
- WebGL (Pixi): тысячи спрайтов; включаем лениво, когда профиль на мобильном покажет просадку.
- Сим и рендер разнесены: сим 30 Гц (детерминизм и дешевле CPU) + рендер с интерполяцией — стандартный приём survivors-игр.

### 3.3. Границы архитектуры (в терминах CLAUDE.md)

- `game/arcade/` — чистое ядро: `createArcadeSim(seed, config)`, `step(input)`, `snapshot()`; никакого DOM/Canvas/React. Тестируется как «N тиков бит-в-бит на двух прогонах».
- `features/arcade/` — экран: `<canvas>` + React-HUD (таймер, HP, XP, золото, карточки уровня). Рендерер за интерфейсом `ArcadeRenderer` (Canvas2D сейчас, Pixi потом).
- `state/arcadeStore.ts` — оркестрация (старт/пауза/level-up/финиш/карьера) — как `managerStore` рядом с `runStore`; mode shell получает шестую карточку `arcade` (offline-режим, без `needsNetwork`).
- Экономика/контент — `game/arcade/content/*.ts` + `ARCADE` в `game/balance.ts` с собственной версией.

## 4. Риски и как их гасим

1. **Арт.** Без анимаций survivors выглядит «программерски». Смягчение: стиль жетонов + сильные VFX и juice (у нас есть скилл `game-feel-juice`), затем решение по спрайтам после go.
2. **Права.** Портреты героев и иконки предметов — арт Valve; используем как и сейчас (некоммерческий фан-проект, атрибуция). Не тащим модели/анимации/звуки из клиента.
3. **Фокус проекта.** Режим не пересекается с драфт-ядром и может растянуть репозиторий. Смягчение: жёсткая изоляция в `game/arcade`+`features/arcade`, отдельная версия баланса, отдельная вкладка Штаба; go/no-go после среза 0.
4. **Мобильный тач.** Джойстик + автоприцел обязательны с первого среза (DMD на ПК, у нас TMA).
5. **Детерминизм под плавающей точкой.** Заложить правила (LUT, без `Math.*` трансцендентных) в срезе 0, иначе реплей и дейлик не получатся потом.
