# Аркада: спрайты из моделей Dota 2 (путь А, BACKLOG T13.13)

Цель: герои, крипы, Рошан и земля в Аркаде выглядят как в Dota, потому что это и есть модели Dota,
отрендеренные в 2D-листы кадров со штатными анимациями. Пайплайн: клиент Dota 2 → Source 2 Viewer CLI
(glTF с анимациями и материалами) → Blender-скрипт `web/scripts/blender/render_dota_sprites.py`
(лист PNG + JSON-мета; конвейер §4а квантует PNG pngquant и перегоняет в lossless WebP, PNG удаляется) →
`web/public/art/sprites/`: `dota/` — обычные листы, `dota_px2/` и `dota_px/` — пиксельные (§7, режим по умолчанию) →
игра подхватывает автоматически (приоритет над LPC и ригами).

Правовая рамка: некоммерческий фан-проект, из клиента берётся только визуал, атрибуция Valve
уже есть в UI и `manifest.source`. Ничего из клиента не распространяем отдельно от игры.

## 0. Что понадобится (один раз)
- Клиент Dota 2 в Steam (нужен `pak01_dir.vpk` и соседние `pak01_*.vpk`).
- **Source 2 Viewer CLI** — https://github.com/ValveResourceFormat/ValveResourceFormat/releases
  (архив `Source2Viewer-CLI` под свою ОС; есть macOS arm64/x64). Распаковать, дать права на запуск.
- **Blender 4.x** — https://www.blender.org/download/ (нужен только бинарник `blender`).
- Пути ниже для macOS; на Windows те же команды, только путь к Steam другой.

```bash
DOTA="$HOME/Library/Application Support/Steam/steamapps/common/dota 2 beta/game/dota"
S2V=~/Downloads/Source2Viewer-CLI/Source2Viewer-CLI   # где распаковал
OUT=~/dota-export
```

## 1. Найти модели
Список файлов по маске (быстро, ничего не распаковывает):
```bash
"$S2V" -i "$DOTA/pak01_dir.vpk" -l -f models/heroes/juggernaut/ -e vmdl_c
"$S2V" -i "$DOTA/pak01_dir.vpk" -l -f models/creeps/neutral_creeps/n_creep_kobold/ -e vmdl_c
"$S2V" -i "$DOTA/pak01_dir.vpk" -l -f models/creeps/roshan/ -e vmdl_c
```
Нужны файлы вида `.../juggernaut.vmdl_c`, `.../n_creep_kobold.vmdl_c`, `.../roshan.vmdl_c`
(у героев базовая модель — только тело: штаны, маска, оружие, наручи, плащ лежат рядом отдельными `vmdl_c` и пришиваются к скелету параметром `--parts` / четвёртой колонкой манифеста; у крипов и Рошана всё в одной модели).

## 2. Экспорт в glTF с анимациями и материалами
```bash
"$S2V" -i "$DOTA/pak01_dir.vpk" -f models/heroes/juggernaut/juggernaut.vmdl_c \
  -o "$OUT/juggernaut" -d --gltf_export_format glb --gltf_export_animations --gltf_export_materials --gltf_textures_adapt
```
То же для кобольда и Рошана (папки `$OUT/kobold`, `$OUT/roshan`). В выходной папке появится
`*.glb` (модель + текстуры + все анимации). Список анимаций модели можно ограничить, если glb
тяжёлый: `--gltf_animation_list "idle,run,attack,death"` (имена — как в файле; посмотреть их
можно, открыв glb в Blender: вкладка Action).

## 3. Рендер листа кадров
```bash
cd /Users/Shared/Coding/aegis-draft/web/scripts/blender
/Applications/Blender.app/Contents/MacOS/Blender -b -P render_dota_sprites.py -- \
  --glb "$OUT/juggernaut/models/heroes/juggernaut/juggernaut.glb" --name juggernaut \
  --out ../../public/art/sprites/dota --dirs 8 --frame 128 --fps 12 --world 84 \
  --anims "walk=run,idle=idle,attack=attack,death=death"
```
Параметры:
- `--anims` — наши состояния = подстроки имён анимаций модели. У героев обычно `idle`, `run`,
  `attack`, `death`; у крипов `run`/`attack`/`death`; у Рошана `roshan_attack`, `roshan_death` —
  подстрока `attack` их найдёт. Нет анимации — состояние пропускается, игра подставит walk/idle.
- `--dirs 8` — восемь направлений (0 = лицом к камере, дальше против часовой на экране: вниз → вправо → вверх → влево). Для крипов хватит 4.
- `--world` — высота спрайта в игровых пикселях: герой 84, кобольд 56, огр 110, Рошан 180.
- `--pitch 42` — высота камеры над горизонтом (90 = строго сверху; 42 читается как RTS/DMD, 58 — ближе к Dota, но силуэты хуже). `--yaw-offset 90`, если модель
  в кадре стоит боком (значит, в файле она смотрит по +X, а не по −Y).
- `--frame 128` — кадр 128×128 (Рошану дать 256).
- `attack=attack@0.12-0.7` — брать только часть клипа (доли длительности). У клипов Dota длинный замах и возврат,
  а урон в игре наносится в начале окна анимации — оставляем сам удар (у героев ~0.12–0.7, у крипов 0.1–0.75).
- `--parts a.glb,b.glb` — части героя (штаны/маска/оружие/наручи/плащ). **Экспортируй части тоже с
  `--gltf_export_animations`**: без него CLI не пишет скин (скелет + веса), и часть застывает в bind-позе рядом
  с бегущим телом («два персонажа»). Скрипт не пересаживает меши частей на скелет тела (у тела кости без
  весов, например `sword_1`, экспортируются с вырожденной позой покоя, и меч уезжает от руки), а ставит на каждую
  кость части Copy Transforms с одноимённой костью тела (имена сравниваются без учёта регистра). Служебная
  «Icosphere» из каждого glb VRF выкидывается.
- После рендера конвейер прогоняет лист через `pngquant` (если стоит, `brew install pngquant`): 256 цветов,
  лист худеет в 4–5 раз (Juggernaut 6 МБ → 1.1 МБ) без видимой потери на 128 px.

Результат: `web/public/art/sprites/dota/juggernaut.png` + `juggernaut.json`; конвейер §4а после pngquant перегоняет PNG
в `juggernaut.webp` (lossless) и удаляет PNG — игра грузит только `<id>.json` + `<id>.webp`. Имя листа = id героя
в игре (`juggernaut`, `crystal_maiden`, `sniper`, `axe`, `zeus`, шаблонные — их id из
`content/heroes.ts`) или id врага (`kobold`, `kobold_foreman`, `hill_troll`, `satyr`, `ogre`,
`centaur`, `wildwing`, `lane_creep`, `siege_creep`, `golem`, `roshan`, `tormentor`, `dark_troll`,
`hellbear`, `ancient`). Игра ищет `dota/<id>.json`; нашла — рисует ей, нет — LPC/риг.

Модели Dota, которые уже в манифесте `web/scripts/blender/dota_manifest.tsv` (проверенные пути в vpk):

## 4. Земля
Текстуры террейна лежат в `maps/<набор>_assets/blends/` (наборы `jungle`, `summer`, `cavern`, `reef`, `journey`, `ti10`; `materials/terrain/` пуст). Экспорт конкретных файлов:
```bash
"$S2V" -i "$DOTA/pak01_dir.vpk" -l -f maps/jungle_assets/blends/ | grep color   # список
"$S2V" -i "$DOTA/pak01_dir.vpk" -f maps/jungle_assets/blends/plants_01_color_psd_8552850e.vtex_c -o "$OUT/terrain/" -d
"$S2V" -i "$DOTA/pak01_dir.vpk" -f maps/jungle_assets/blends/radiant_jungle_dirt_01_color_psd_133dcf93.vtex_c -o "$OUT/terrain/" -d
```
Осторожно: часть «травы» (например, `summer_assets/.../grass_long_*`) — белые маски, которые красит шейдер; нужны текстуры с готовым цветом.
Из полученных PNG нужны бесшовные: трава Radiant (`*grass*`/`*radiant*`), земля/тропа (`*dirt*`),
для акта 2 — трава Dire, вода для реки. Положить как:
`web/public/art/sprites/dota/terrain/grass.webp`, `dirt.webp`, `grass_dire.webp`, `water.webp`
(любой квадрат 256–1024 px, сейчас 512; PNG перегнать `cwebp -lossless` — загрузчик берёт только `.webp`).
Игра замостит ими землю паттерном вместо тайлов LPC; пиксельные 128-px версии лежат в `dota_px/terrain/` (§7).

## 6. Звуки ударов героев
```bash

```
Скрипт выгружает `sounds/weapons/hero/<папка>/` (имена папок Valve отличаются: `zuus`, `bristlebog`, `nevermore`, `windrunner`, `antimage` — таблица в скрипте), берёт `attack*`/`*swing*`, `preattack*`, `impact*`, жмёт `afconvert` в AAC mono 40 kbps и пишет `public/art/sfx/dota/index.json`. Игра (`features/arcade/heroSfx.ts`) играет клип героя на каждый удар, петлю Blade Fury у Juggernaut; нет клипов — синтетика. Арканы/сеты: `arcana_*` файлы в тех же папках — под T13.12.
- **Скины и базовые префиксы (2026-09-06):** в папке `sounds/vo/<hero>/` лежат вперемешку база, арканы и персоны; базовый
  префикс определять по именам `*_move_01.vsnd_c` (S2V -l), не по частоте: Razor — `raz_` (`rz_vsa_` — аркана), Dragon Knight —
  `drag_` (`dk_davion_`/`dk_slyrak_` — персоны), Earthshaker — `erth_` (`earth_arcana_`), QoP — `pain_` (`qop_arc_`), Ogre —
  `ogmag_` (`ogm_arc_`). Скин со своей озвучкой — отдельная запись `hero@skin:папка:префикс` в `dota_voice.sh`; токены скинов
  (`_arc_`, `_vsa_`, `_per_`, `_davion_`, `persona`, …) исключаются из базы, но не из набора самого скина. Скин без своей
  озвучки (арканы CM/PA) говорит голосом базового героя (`voiceKey` в `heroSfx.ts`).

## 7. Пиксельный стиль (Dead Cells-подход) — пилот
Решение владельца 2026-09-06: режим должен выглядеть пиксельным, ориентир — Dead Cells (детальный пиксель, не 8-бит).
Те же модели, тот же конвейер, меняется последний шаг:
- `render_dota_sprites.py --pixel`: движок **Workbench** (плоская заливка текстурой цвета, студийный свет без бликов и теней,
  чёрный контур по силуэту, cavity для рёбер, сглаживание выключено); кадр **48 px** для героев, 36 — крипы, 72 — деревья
  (исходный кадр / 2.67); `--world` = 2 × кадр, чтобы при внутреннем масштабе игры ×2 спрайт ложился 1:1 в пиксели.
  Workbench в режиме TEXTURE берёт *активный* узел-картинку материала — скрипт делает активной текстуру `*_color*`
  (иначе первым идёт detailmask и силуэт выходит чёрным).
- Палитра: `pngquant --nofs 48` (без дизеринга — ровные пятна). Листы кладутся рядом: `public/art/sprites/dota_px/`
  (`SPRITES=…/dota_px bash dota_pipeline.sh manifest_px.tsv`), обычные остаются в `dota/`.
- Игра: `?pixel=2` включает пиксельный проход рендера (мир рисуется в буфер 1/2 и растягивается nearest) и переключает
  загрузчик на `dota_px/` с фолбэком на `dota/`; земля — `dota_px/terrain/*` (256 px, 20 цветов).
- Пилот: Juggernaut, Shadow Fiend, Crystal Maiden, кобольд, дуб, камень. Дальше по решению владельца — весь манифест.
- **Два набора пиксельных листов (2026-09-06):** `dota_px/` (`dota_manifest_px.tsv`) — для фактора 2 (обычный монитор) и
  `dota_px2/` (кадр ×2 при том же `--world`, `dota_manifest_px2.tsv`) — для фактора 1 (Retina/телефон: 1 CSS px на арт-пиксель =
  2 физических). Кадры сейчас: герои — 80 (`dota_px`) / 160 (`dota_px2`) при `--world 160` и запасе `--margin 1.4`; крипы —
  48 / 96, крупные враги — 64 / 128 (у старых листов поля `margin` в мете нет — это 1.12). Фактор выбирает
  `features/arcade/pixelMode.ts` по DPR; загрузчик листов идёт
  `dota_px2 → dota_px → dota`. Перерендер всего набора: `SPRITES=…/dota_px2 OUT=<экспорт> S2V=<cli> bash dota_pipeline.sh dota_manifest_px2.tsv`
  (~30 мин на 47 листов, S2V экспортирует glb заново — это нормально).
- **Тёмные модели (Shadow Fiend, Рошан):** color-текстура SF почти чёрная (средняя яркость 0.017 — в Dota он светится
  selfillum/spec, чего у Workbench нет). `--pixel` теперь делает автоэкспозицию: если средняя яркость непрозрачных пикселей
  текстуры ниже `--autoexpose` (0.16), пиксели поднимаются гаммой до `--expose-target` (0.4) прямо в картинке (Workbench граф
  узлов не считает). `--light` для таких моделей всё равно держать 1.5–1.7.
- **Земля:** `web/scripts/pixel_terrain.mts` (Playwright-canvas, без sharp/PIL) делает из 512-px `dota/terrain/<name>.webp` пиксельные
  128-px текстуры `dota_px/terrain/<name>.webp` (WebP quality 1 в Chromium — без потерь). Запуск из `web/`:
  `npx tsx scripts/pixel_terrain.mts 0.2 0.3 2` — закоммиченная земля собрана именно с этими аргументами (`lum contrast div`),
  умолчания в коде давят нижние ступени в чёрный. Сами текстуры: усреднение до 64, 5 ступеней яркости лестницей контраста вокруг
  среднего цвета, затемнение под тон карты. Старые 4-битные PNG рисовались ровной «мутью» — контраст исходников Dota почти нулевой.
  В игре тексель = 2 внутренних пикселя при любом факторе (`texScale = 2·фактор`).

## 7а. Вес листов: смерть в одном направлении, без набора `dota/` (2026-09-19)

Сайт живёт на GitHub Pages (лимит ~1 ГБ), спрайты — основной вес. Два решения по замерам:
- **Клип `death` — одно направление.** В игре он рисуется в единственном месте (гибель врага, `renderer.ts` ветка `"die"`) и всегда
  в направлении 0; смерть героя с листа не проигрывается. Семь из восьми рядов смерти у ~1300 листов никто не рисовал (~17–25%
  веса листа). `render_dota_sprites.py --single-dir death` (по умолчанию) рендерит такие клипы только лицом к камере и пишет
  в мету клипа `dirs: 1`; готовые листы перекладывает `scripts/sheet_single_dir.mts` — без перерендера и побайтно без потерь
  (`dwebp -pam` → перенос рядов → `cwebp -lossless -exact`; canvas браузера не годится: премультипликация альфы портит
  полупрозрачные края). Читатели рядов берут `a.dirs ?? meta.dirs`. Перекодирование WebP сильнее (`-z 9`, near-lossless)
  не даёт ничего (≈1%): листы уже оптимальны.
- **Непиксельный набор `dota/` удалён** (41 лист первых героев, −31 МБ): в пиксельных наборах есть всё, а `?pixel=0` — отладочный
  режим и теперь рисует те же пиксельные листы без пиксельного прохода. Исходники земли 512 px переехали в
  `scripts/blender/terrain_src/` (их читает `pixel_terrain.mts`). Упоминания `public/art/sprites/dota/` выше в этом документе —
  история пилота.
- Резерв, если места снова не хватит: зеркалить 3 из 8 направлений (−37%, но оружие меняет руку), пережать озвучку
  (97 МБ mp3 128 кбит/с стерео → моно 64: ≈ −40 МБ), вынести `art/sprites` на отдельный хостинг.

## 8. Облик по слотам: слои частей и скины призывов (T13.80)

Гардероб собирает облик из частей разных сетов (меч одного, шлем другого — и на аркане тоже), как в Dota.
Пре-рендеренных листов на все сочетания не напасёшься, поэтому лист собирается в рантайме: **тело основы без
сменных частей** (`<основа>+body`) плюс **слой на каждую часть** (`<основа>+<источник>.<слот>`), слои рисуются друг
на друга в порядке слотов (`features/arcade/sprites.ts`, `compositeSheet`). Слой = разница рендеров «тело» и «тело +
части слота» (`sprite_part_layer.mts`): Workbench не умеет holdout, а разница даёт ровно видимые пиксели части с
правильным перекрытием телом.

**Основа = семейство** (срез 2, 2026-09-15). У героя несколько тел: базовая модель `<hero>`, аркана `<hero>@arcana`
(другая модель у Jugg, другая текстура тела у MK и Lina) и её стили `<hero>@arcana~style1`. Слои с одного тела на
другое не ложатся (перекрытия и тени телом другие), поэтому у каждого семейства свои `+body` и свои слои. Источники
частей внутри семейства: `base` (части модели по умолчанию — все, включая те, которых у арканы нет, например плащ Jugg),
имя основы (`arcana` — её собственные части: маска Jugg, голова MK, пламя Lina) и сеты `<hero>@<set>` с базового тела.
Части сета на аркане берутся с подменами `asset_modifier model` из `items_game` (аркана MK подменяет сет Cult на
`*_arcana_*`). Слоты по умолчанию семейства — части строки основы в основном манифесте: у арканы Jugg слот спины пуст,
как в Dota. Всё это собирает `dota_part_layers.mts` и пишет в `src/game/arcade/content/parts.ts`
(`HERO_PARTS[hero].families[<основа>]`).

**Слот части — по данным Dota, не по имени файла.** `scripts/dota_item_index.mts` парсит `items_game.txt` из vpk
(KeyValues, наследование `prefab`) и пишет `scripts/blender/dota_item_index.json`: путь модели → item ID, `item_slot`,
редкость, подмены моделей; плюс основы `hero_base` по героям. Модели без предмета (волосы Axe, плащ MK) — в
`dota_slot_overrides.json` с причиной; неизвестная модель **останавливает** генератор, а не уходит в misc (аудит
2026-09-15: догадка по имени клала голову арканы MK в misc, наручи Lina в misc, воротник — в shoulder, а под
`lina@arcana` лежал сет Battle Caster). Семантический слот и порядок отрисовки — разные вещи: порядок — `DRAW_ORDER`
в `scripts/lib/dota_slots.mjs`, слот Dota вне него генератор тоже не берёт.

Два условия, без которых слои не лягут: **одно кадрирование** у всей семьи (центр, высота и охват меряются пробным
рендером силуэта, у голого тела и тела с плащом они разные) — `--fit-from <образец.json>` в `render_dota_sprites.py`
берёт поле `fit` из меты листа-образца (строка основы, `<основа>+ref`); и **сырые листы** без палитры — `RAW=1` в
`dota_pipeline.sh` (разные палитры двух листов дают шум по всему телу).

```bash
cd web && D=/tmp/parts
npx tsx scripts/dota_item_index.mts                                   # индекс предметов из vpk (после правок манифестов)
npx tsx scripts/dota_part_layers.mts plan --heroes juggernaut --families juggernaut@arcana,juggernaut@arcana~style1 --dir $D
RAW=1 REUSE=1 OUT=$D/export SPRITES=$D/px2 bash scripts/blender/dota_pipeline.sh $D/family_px2.tsv
RAW=1 REUSE=1 OUT=$D/export SPRITES=$D/px  bash scripts/blender/dota_pipeline.sh $D/family_px.tsv
npx tsx scripts/dota_part_layers.mts build --heroes juggernaut --families juggernaut@arcana,juggernaut@arcana~style1 --dir $D
npx tsx scripts/dota_part_layers.mts table                            # parts.ts из манифестов слоёв (и после переименований)
```

`REUSE=1` теперь не только не экспортирует glb повторно, но и не тянет заново текстуры стиля / fix-tex / маски
свечения, если они уже лежат в экспортной папке основы (у семьи со `--style` листинг vpk и 39 текстур MK стоили
почти минуту на каждую строку). Волна по многим героям — `bash scripts/dota_part_wave.sh <scratch> <hero>…`: для каждого plan → рендер px2/px → build,
возобновляемо (герой со слоями пропускается), герой с моделью без слота пропускается с записью в `wave.log`.
**Закреплённые слоты** (`scripts/blender/dota_part_exclusions.json`): запись `<основа>.<слот>: { only, why }` — остальные
источники этот слот семейству (и его стилям) не дают: слой не планируется и в гардеробе не предлагается. Заводится только по
замеру `npx tsx scripts/qa_part_attach.mts [dota_px] [--min 0.15]` — доля кадров, где слой не касается силуэта героя (тело +
остальные слои по умолчанию); у правильно сидящей части ≈ 0, у лука на аркане Drow (свой хват арбалета, refit-луков в vpk
нет) — 38–46%. Гонять после каждой новой семьи слоёв на теле арканы/персоны. Базовые части на аркане тоже проходят через
подмены предметов арканы (колчан Drow → `drow_quiver_refit`).
**Порядок слоя спины по направлениям** (`backOrder` в `parts.ts`): слой — разница с голым телом и взаимных перекрытий частей
не знает; лицом к камере плащ/крылья под бронёй, спиной к камере — поверх (иначе «крылья просвечивают сквозь скин»). `table`
меряет три варианта (спина первой / перед головой и оружием / последней) против цельного листа по каждому направлению и
пишет лучший; рантайм рисует слой спины по рядам направлений (`sprites.ts drawLayers`). **Сет-перекраска** (`--style dpc` у
Spring Lineage SF): строка сета может отличаться от базовой хвостом `--style <токен> [--style-folder <папка героя в vpk>]` —
слои такого источника рендерятся с тем же хвостом; `--style-folder` нужен, когда предметы лежат не в папке модели
(SF: модель `heroes/shadow_fiend`, предметы `items/nevermore`).
`--only <префикс id>` в `plan`/`build` ограничивает семью (например `--only juggernaut@arcana` — только арканные
семейства, базовое не перерендеривается). `build` публикует семейство целиком или не публикует вовсе (нет рендера
слоя — стоп), заменяет строки с тем же id в `dota_manifest_parts_{px2,px}.tsv` и печатает долю расхождения композита
«тело + слои по умолчанию» с образцом — диагностический замер сырых PNG, а не гарантия качества готового WebP
(срез 1: 1.5–9.8% в px2 и 2.4–13.5% в px). Порог принимается по визуальному пилоту; проверять и готовые WebP, и
смешанные наборы во всех направлениях: порядок слоёв не учитывает все взаимные перекрытия деталей. См. [аудит
2026-09-15](audits/2026-09-15-customization.md). Слои живут в манифестах слоёв (не в основном: их не рендерят
напрямую). Сет со стилями (`~style` у сета) в слоях — в базовом стиле; стиль **основы** — своё семейство, а если оно
не отрендерено, смешанный облик показывается на основе без стиля и гардероб это пишет (`styleDropped`).

**Скины призывов** (медведь Lone Druid, волки Lycan, паучки Brood, голем Warlock) — полная модель скина из
`models/items/<hero>/<bear|wolves|spiderling|golem>/…` на скелете и анимациях базового призыва: строка
`<art>@<skin>` в основных манифестах с `--hide-base` и моделью скина в колонке частей. Косметика —
слот `summon` в `cosmetics.ts`, надевается в гардеробе героя, в сим не идёт. **Волки Lycan** (срез 3, 2026-09-19) — исключение:
у моделей скинов свой скелет (`Bip01…` без пары в `lycan_wolf`), на чужом скелете меш растягивается в полосу, поэтому строка
`wolf@<skin>` рендерит **саму модель скина основной** (без `--hide-base` и частей) — клипы `run/idle/attack/death` у неё свои.

**Скины форм** (срез 3): Метаморфоза Terrorblade, True Form Lone Druid, дракон Dragon Knight. В Dota это отдельные предметы в
своих слотах (`ability3`, `ability_ultimate`, `shapeshift`) с подменой модели формы (`asset_modifier hero_model_change`), поэтому
в игре форма выбирается независимо от облика: слот косметики `form`, `cosmetics.formSkins[hero]`, лист `<hero>@meta~<имя>` —
строка со скелетом и аргументами базовой формы `<hero>@meta`, `--hide-base` и моделью скина в частях (у TB маска свечения
берётся из папки материалов скина). Приоритет в рендерере: скин формы → форма надетого облика `<hero>@<skin>@meta` → базовая.
Идентичность строк держит тест `arcadeForms`: модель обязана значиться в `dota_item_index.json` (`entityModels`) подменой
именно базовой формы этого героя (волки — подменой юнита `npc_dota_lycan_wolf`).

## Что делать, если
- Модель серая/без текстур: перезапустить экспорт с `--gltf_export_materials --gltf_textures_adapt`;
  если текстуры всё равно не легли — открыть glb в Blender вручную и проверить Material Preview.
- Анимация статична: экспорт был без `--gltf_export_animations`, либо имя не совпало с `--anims`
  (посмотреть список: в Blender после импорта — Dope Sheet → Action Editor).
- Часть героя (меч/штаны/маска) стоит на месте, а тело бежит: часть экспортирована без
  `--gltf_export_animations` (скрипт пишет `WARN: у части … нет скелета`). Меч в руке, но не там, где рука:
  проверь, что скрипт свежий (Copy Transforms по костям, а не пересадка меша на скелет тела).
- Удар «рукой», меч не участвует: смотри, что в `--parts` есть модель оружия и что у неё есть кость `sword_1`
  (или аналог) в скелете тела; в кадрах удара клип обрезан `@0.12-0.7`, замах и возврат вырезаны.
- Герой пропадает в части кадров бега: гашение root motion не отключается по порогу, а **обрезается**
  по нему (`render_dota_sprites.py`, `lim = extent * 0.5`). Проверка всех листов разом —
  `npx tsx scripts/qa_frame_gaps.mts [dota_px2] [walk]`: печатает листы, где силуэт пропадает.
  Соседняя проверка `qa_frame_drift.mts` ловит то же на подходе — листы, где герой ещё виден, но
  уполз к краю кадра (порог по умолчанию 25% кадра): их стоит перерендерить до того, как пропадут.
- Аркана/сет выглядит месивом: скорее всего рендер взял **не ту** модель. `Source2Viewer-CLI -d` тянет
  и зависимости (у `drow_arcana.vmdl_c` это базовое тело `drow_base`), поэтому `dota_pipeline.sh` берёт
  glb строго по пути из манифеста, а не первый попавшийся. Второй источник месива — группы тела:
  CLI выгружает каждую отдельной моделью, и у косметики это три совпадающих меша (`._dummy`, базовый,
  `<имя>_style1`); скрипт схлопывает их (`drop_dupes`), оставляя базовый — стиль у нас делается
  подменой текстур (`--style`), а не выбором меша.
- Спрайт стоит боком: `--yaw-offset 90` (или −90).
- **Герой в беге чередует две позы («дёргается»)**: клип бега длиннее окна листа (у Muerta `run` — 7 с), и 12 кадров
  на весь клип давали шаг выборки 0.58 с при цикле шага ~0.5 с. Рендер сам находит период цикла автокорреляцией позы
  (`loop_period`, сдвиги 0.2–2.5 с) и берёт один период; не нашёл — первую секунду клипа. Замер — `qa_sheet_health.mts`,
  колонка «строб» (1 = чистое чередование).
- **Аркана из частей — «размазня», тело в bind-позе**: клипы для рядов брались из ВСЕХ glb, включая части, и у плаща
  арканы Drow `cloth_IDLE`/`cloth_DEATH` выигрывали у `drow_arc_idle` как более короткие имена. Клипы теперь только из
  основной модели (`main_actions`). Симметричные части (наручи, ноги) выкидывались как «дубли» по числу вершин и
  габариту — теперь дубль = совпадающая геометрия.
- **Герой выбегает из кадра / ряд каста пустой**: гашение root motion считается по НЕСУЩЕЙ кости (самая тяжёлая по весу вершин
  из костей туловища — spine/pelvis/root; голова не годится: при смерти она уходит на пол вперёд и тело уезжает за
  нижний край кадра), относительно позы кадрирования, без порогов. Корень не годится (у Vengeful
  Spirit и персоны Mirana он стоит, а тело едет дочерней костью); «самая быстрая кость» тоже (при ударе это локоть).
  Пустой каст — служебный клип (`mvp_screen` у персоны DK, `cast_dig` у Meepo под пол): такие токены в чёрном списке
  `pick_action`, а Meepo получил `cast=earthbind|cast`.
- **Тёмная аркана сплошь чёрная (PA, Terrorblade), но со светлыми деталями**: раньше автоэкспозиция такие текстуры
  пропускала целиком. Теперь при p99 ≥ 0.4 — мягкая гамма к 0.3 от среднего (не ниже 0.5), света не трогаются.
  Узор свечения в альфе цвета (PA «Manifold Paradox») закрашивается `--glow-from-alpha R,G,B`; свечение из масок
  selfillum (грудь Terrorblade) — `--glow-mask <папка материалов>` (+ `--glow-color`), пайплайн достаёт
  `*_detailmask_*`/`*_selfillummask_*` из vpk сам (в glb альфы масок нет).
- **Модель серая без текстур, а в логе S2V `Failed to load materials/models/heroes_staging/…`** (ремодель арканы QoP):
  материалов в vpk нет, VRF пишет меш без них, Blender сливает примитивы в один серый меш. Лечится `--fix-tex <папка
  материалов в vpk>` (пайплайн достаёт color-текстуры) + `--mat-map 0=<текстура>,1=…` по номерам примитивов (порядок =
  порядок «Loading material» в логе S2V) или по именам материалов-заглушек (`alexgrey=…`).
- **Чёрное «знамя» или плоскость на герое** (грива арканы Jugg): additive/скролл-материал — текстура с чёрным фоном,
  который в Dota невидим, а в Workbench рисуется. `--drop-mat <regex по имени материала>` снимает грани таких
  материалов (меш без граней уходит целиком); сердцевину огня (`tail_core`, листья на альфе) красит `--glow-from-alpha`.
  Список материалов и их bbox — Blender `-b --python-expr` по glb (см. T13.33 в BACKLOG).
- **Скин собран не из тех частей** (аркана Jugg ходила в базовой маске и меховом плаще): у строки `@skin` 4-я колонка —
  это слоты Dota: что аркана заменяет (маска → `models/items/<hero>/arcana/…`), то из папки скина, что не заменяет
  (ноги `juggernaut_pants`, меч, наручи) — базовые как были. Тело арканы может быть одним торсом без ног: проверь
  bbox меша в Blender (`evaluated_get`), прежде чем винить анимацию.
- **Ткань/грива торчит палкой**: кости цепочки (`chain_*`) без пары в теле идут за родителем, физики нет.
  `--drop-vgroup <regex по кости>` убирает грани дальних звеньев (`chain_[3-9]` — половина гривы).
- **Скин «голый»: нет плаща/капюшона** (аркана PA): проверь вершины на костях ткани (`cape_*`) — если их ноль, это частицы
  (`*.vpcf`), в спрайт не попадут. Замена — эффект скина `fx.aura` в `content/cosmetics.ts` (вид в `effects.ts`, как `veil`).
  Узор в альфе color-текстуры — `--glow-from-alpha` цветом свечения, не белым (белый читается как кожа). Альфу и яркость
  смотреть Blender + numpy по PNG. `--white-to R,G,B[,порог]` есть для белой ткани, но у PA белого почти нет (1%).
- **Самоцвет красит не те пиксели**: рендер пишет `glow` (тон, градусы) в мету листа, когда заданы `--glow-color`/`--glow-from-alpha`;
  `gemSheet` красит пиксели этого тона с мягкими порогами. Без `glow` в мете — скан доминирующего тона, как раньше.
- **Свечение есть в vpk, но не видно в кадре** (грудь Terrorblade): маска selfillum точечная — `--glow-grow N` расширяет её на N текселей.
  Если маски нет вовсе (клинки TB красит градиент `*_grad`), `--glow-mat <regex>=R,G,B[,сила]` тянет светлые места материала к цвету.
- **Стиль арканы (`~style1`) выглядит как базовый**: в строке манифеста нет `--style style1` (так было у QoP).
- **Самоцветы в игре** — не пайплайн: `gemSheet` в `features/arcade/sprites.ts` перекрашивает акцентные пиксели листа
  (яркие, насыщенные, в тоне доминирующего акцента) и кладёт ореол; облик без свечения самоцветов не показывает.
- Проверка всех листов разом: `npx tsx scripts/qa_sheet_health.mts dota_px2` — ранжирует по стробу, рывку, провалу
  силуэта, кускам, темноте/серости и пустым кадрам. Перерендер без повторного экспорта glb — `REUSE=1`.
- Слишком тёмно/светло: `--pitch` и свет заданы в скрипте (`setup_camera_and_lights`), правится там.
