# Обновление общих скиллов — 2026-09-09

## Результат

Единый набор из 16 канонических скиллов в `.claude/skills`: 11 обновлённых профильных, перенесённый общий router `aegis-draft` и четыре новых. `.agents/skills` и `.codex/skills` содержат относительные ссылки на все 16 каталогов. Редактируемых копий больше нет. Обновлены INDEX, PRINCIPLES, CLAUDE, адаптер Cursor и README; в CI добавлена самостоятельная проверка скиллов. Игровой код, данные и продуктовые решения этой работой не менялись.

## Что было не так

- В `.agents/skills` было шесть устаревших копий. У data-contract расходился validator и отсутствовал dataset_shape; расходился antipatterns-сканер. Сохранены актуальные канонические инструменты, старые оригиналы перед заменой перемещены в резервную папку вне репозитория.
- `.codex/skills` содержал отдельный router и десять ссылок, без game-feel-juice. Router теперь тоже канонический.
- У scoring-model некавыченная YAML-строка содержала двоеточие с пробелом; описания были длинными, ссылки часто имели непереносимый wiki-формат.
- Plan/discovery требовали повторных согласований даже для порученной обратимой работы. Теперь вопрос задаётся по значимой нерешённой зависимости.
- Self-review предлагал запуск mock поверх рабочего датасета и восстановление через checkout. Теперь требуются изолированная копия/CI и сохранение чужих изменений.
- Data-contract ссылался на несуществующую генерацию TS. Сейчас `web/src/types/data.ts` синхронизируется вручную; область скилла ограничена статическим ETL-контрактом.
- Backend предлагал прямой импорт `pipeline/internal/*` из отдельного Go-модуля. Теперь учитывается граница internal и различаются целевая архитектура ADR и фактическая реализация.
- Game-state описывал существующую оркестрацию как будущую; game-feel переносил ограничения DOM на весь игровой цикл. Правила уточнены.
- Reference audit требовал live parity даже от запроса идей. Теперь исследование, предложения и подтверждённый аудит поведения имеют разный статус доказательства.

## Почему добавлены новые скиллы

| Скилл | Наблюдённая проблема → процедура | Почему существующего недостаточно |
|---|---|---|
| arcade-simulation | Зависание headless на выборе, путаница текста способности с поведением → pending-first прогон, ограничение шагов, проверка статусов и replay | Game-state описывает фазы; scoring-model — draft/OVR, а не бой |
| arcade-assets | Исправление сетов/форм, числовой QA не доказывает правильный риг → существующий pipeline, один пилотный ассет, листы и live QA | Frontend и game-feel не покрывают Blender, wearable-части и manifest |
| save-compatibility | Постоянный unlock зависит от обрезаемой истории; повтор завершения → разделение постоянного прогресса, миграции и идемпотентная награда | Game-state не покрывает весь жизненный цикл сохранённого результата |
| agent-skill-maintenance | Копии расходятся между клиентами → единый источник, адаптеры, YAML/link checks и trigger-набор | Это отдельная повторяемая процедура сопровождения инфраструктуры агента |

Обнаруженные игровые проблемы здесь превращены в проверки процесса, а не незаметные исправления игры. Отдельные localization/model-specific скиллы не добавлялись: соответствующие процедуры уже покрыты или не имеют обоснованного отдельного процесса.

## Официальные источники и применённые решения

Источники проверены 2026-09-09; детали загрузчика следует перепроверять при обновлении клиента.

- [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills) (актуальный переход с developers.openai.com/codex/skills): Codex обнаруживает `.agents/skills`, поддерживает ссылки на каталоги; одинаковые имена не следует считать автоматически слитыми. Поэтому `.agents` является основным адаптером, legacy `.codex` явно отмечен как совместимость.
- [Claude Code: Skills](https://code.claude.com/docs/en/skills): проектные процедуры в `.claude/skills`, YAML metadata и дополнительные ресурсы. В ядре используем общий формат, без обязательных расширений конкретного клиента.
- [Agent Skills specification](https://agentskills.io/specification): требования к name, description и относительным ресурсам. Предел description стандарта — 1024, не 200; локальный бюджет 200 строже стандарта.
- [Anthropic: How to create custom skills](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills): Help Center указывает более короткое описание до 200 символов. Это отдельный документ/контекст; не переносим его как универсальное ограничение Claude Code.
- [Anthropic engineering: Equipping agents for the real world](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills): progressive disclosure и развитие скиллов из наблюдённых затруднений. Поэтому дополнительные каталоги необязательны, новые скиллы обоснованы реальными задачами.
- [Anthropic: The Complete Guide to Building Skills for Claude](https://resources.anthropic.com/hubfs/The-Complete-Guide-to-Building-Skill-for-Claude.pdf): проверка триггеров, поведения и итерации. Добавлены положительные, соседние отрицательные и неоднозначные примеры; статическая проверка отделена от запуска модели.

## Проверка и ограничения

- `quick_validate.py` из доступного OpenAI skill-creator: все 16 скиллов PASS. CI YAML разобран парсером; `git diff --check` без ошибок.
- Канонический validator: 0 ошибок; проверены YAML, названия, локальные Markdown-ссылки и 32 ссылки адаптеров.
- Тесты валидатора: 10 тестов, PASS, включая испорченные метаданные, абсолютные ссылки и разрешённые относительные/web-ссылки.
- [Trigger-набор](skill-trigger-cases.md): 4 положительных и 3 отрицательных сценария для каждого из 16 скиллов; ручной review описаний и 12 walkthrough-сценариев применения. Это не автоматический benchmark модели.
- Antipattern scan завершился с кодом 0; предупреждения относятся к существующим отладочным TS-файлам вне этой задачи.
- Игровая сборка и тесты не запускались: игровые исходники не менялись. CI job добавлен, удалённый CI не запускался, push не выполнялся.
- Настоящая автоактивация в новом сеансе каждого Claude/Codex не проверена. При повторной проверке текущий Codex-сеанс получил все 16 проектных скиллов через `.codex/skills`; это подтверждает доступность каталога в этой среде, но не выбор скилла для произвольного запроса или discovery через `.agents/skills`. Claude CLI не найден в PATH. В клиенте, сканирующем оба адаптера, названия могут повторяться, но тексты и инструменты будут одни и те же.
- `.codex/hooks.json` оставлен без изменений как legacy-конфигурация; исполнение Claude hooks в Codex не предполагается. Проверки доступны явно и в CI.

Инструкция дальнейшего сопровождения и команды — [PRINCIPLES](PRINCIPLES.md).

## Повторная проверка в рабочем дереве

На начало повторной проверки миграция выше уже присутствовала в незакоммиченных изменениях. Она сохранена; дополнительные изменения этой проверки:

- Валидатор теперь отклоняет абсолютные symlink и локальные Markdown-ссылки, даже если они работают в текущем checkout. Добавлены три регрессионных теста в существующий набор.
- Исправлен устаревший совет о генерации TS в `web/README.md`: команды генерации в `web/package.json` нет. В maintenance закреплена проверка документов, на которые опирается discovery.
- В save-compatibility ограничено правило dataHash зависимыми от ETL забегами; replay Аркады проверяет собственную версию правил.
- Официальные страницы OpenAI Build skills, Claude Code Skills, Agent Skills specification и указанные материалы Anthropic повторно открыты. Лимиты и пути клиентов не заменены предположениями о названиях моделей.
- Повторно выполнены оба валидатора для 16 скиллов, все 10 тестов инструмента, разбор CI YAML, antipattern scan и `git diff --check`. Игровые исходники не менялись; оставшиеся предупреждения сканера относятся к ранее существующим TS-файлам.
