# Поддержка проектных скиллов

## Один источник и узкая задача

Редактируем `.claude/skills`. В `.agents/skills` и совместимом `.codex/skills` создаём относительную ссылку каталога `../../.claude/skills/<name>`. Перед заменой старой копии сравниваем весь каталог, включая tools/references, и сохраняем уникальные правила. AGENTS.md ссылается на CLAUDE.md; адаптер Cursor отсылает туда же.

Новый скилл нужен, когда есть наблюдённая повторяемая проблема и собственная процедура. Одно дополнение к проверке добавляется в существующий скилл. Не нужны отдельные версии для Opus/Fable/Astra: различаются возможности клиентов и инструменты, не проектные инварианты.

## Формат

- YAML: `name` совпадает с папкой, 1–64 символа, lowercase kebab-case; `description` коротко задаёт триггер и границу. Используем цитированную строку или корректный YAML block scalar.
- Локальная политика: description до 200 символов, SKILL.md до 500 строк. Это наш переносимый бюджет, не универсальный лимит всех клиентов.
- Основной текст: вход → существенные действия → проверяемый результат. Редкие подробности выносим в references, когда это действительно сокращает основной путь.
- Обычные относительные Markdown-ссылки. Команды — от корня репозитория, если явно не указана другая директория. Не добавляем личные абсолютные пути.
- scripts/tools, assets и agents/openai.yaml необязательны. Не создаём их ради шаблона. Существующие tools сохраняем, поскольку на них ссылаются CI и hooks.
- Не закрепляем исторические количества героев, версии баланса и временные тарифы. Проверяем правила по коду и официальным источникам.
- Не добавляем обязательных согласований поверх авторизованного поручения. Правило игрового confirm при выходе не означает разрешение пользователя на правку кода.

## Проверка

Из корня репозитория, в отдельном Python-окружении (системный Python не менять):

```bash
python3 -m venv /tmp/aegis-skill-check
/tmp/aegis-skill-check/bin/pip install -r .claude/skills/agent-skill-maintenance/tools/requirements.txt
/tmp/aegis-skill-check/bin/python .claude/skills/agent-skill-maintenance/tools/validate_skills.py
/tmp/aegis-skill-check/bin/python -m unittest discover -s .claude/skills/agent-skill-maintenance/tools -p 'test_*.py'
git diff --check
```

Валидатор читает YAML настоящим парсером, проверяет имена/описания, ссылки в Markdown, полный состав адаптеров и INDEX. Абсолютные локальные Markdown-ссылки (включая file URI) и абсолютные symlink отклоняются: совпадение цели на машине автора не доказывает переносимость checkout. Не проверяет доступность внешних URL, якоря и пути внутри произвольного кода/inline code; их проверяют по затронутой процедуре. Негативные тесты ловят поломку метаданных, ссылок и копии вместо symlink.

[Trigger-набор](skill-trigger-cases.md) — качественные сценарии для всех скиллов, не автоматический benchmark. Проверяй выбор по описаниям, затем поведение по тексту. Для изменения триггеров повторяй как положительные, так и соседние отрицательные случаи. Не подменяй проверку модели поиском ключевых слов.

Для настоящего smoke открой новый сеанс каждого установленного клиента из корня проекта, проверь обнаружение каталога и попроси выполнить безопасный сценарий без записи. Зафиксируй версию клиента, найденные пути и фактически прочитанные скиллы. Если это не выполнено, прямо укажи ограничение; статический PASS не означает автоактивацию.

## Совместимость и сопровождение

Claude Code читает `.claude/skills`, Codex документирует `.agents/skills` и symlink-каталоги. `.codex/skills` пока сохранён для текущей установки, где этот каталог представлен в доступных скиллах. При подтверждённом переходе всех используемых клиентов на `.agents/skills` можно отдельно удалить legacy-адаптер и обновить валидатор. Сейчас дубль обнаружения возможен; дубль редактирования запрещён.

`.claude/settings.json` и hooks остаются настройками Claude Code. Наличие `.codex/hooks.json` не доказывает выполнение этих hooks в Codex; переносимость проверок обеспечивают явные команды и CI. Права инструментов этим обновлением не расширяются.

В конце значимой сессии оцени, возникла ли повторяемая ошибка процесса. Обновляй скилл по доказательству, а не ради обязательной правки после каждого разговора. См. [agent-skill-maintenance](../../.claude/skills/agent-skill-maintenance/SKILL.md) и [проверенные официальные источники](2026-09-09-skills-refresh.md).
