# Сначала найди готовое

1. Уточни для себя ожидаемое поведение и прочитай материалы пользователя. Объём поиска соразмерен изменению.
2. Найди карту нужной области в [README](../../../README.md), [PRD](../../../docs/PRD.md), [schema README](../../../schema/README.md), [pipeline README](../../../pipeline/README.md) и [web README](../../../web/README.md). Читай релевантные разделы, а не все документы целиком при каждой функции.
3. Используй `rg --files` и `rg` по нескольким смысловым терминам. Проверь определения, вызовы и тесты ближайшего аналога. Отсутствие точного имени не доказывает отсутствие решения.
4. Выбери существующую точку расширения. Для UI сначала `web/src/ui/index.ts`; для статики — schema и DataSource; для Аркады — её sim/content, а не draft engine.
5. Кратко зафиксируй найденное: «Переиспользую A и B; добавляю Q, поскольку найденный C не покрывает …». Если аналога не найдено, укажи область поиска без заявления о доказанном отсутствии во всём проекте.

Расширение почти подходящего модуля и выбор между обратимыми вариантами обычно входят в поручение. Не останавливай работу только из-за этого. Важную продуктовую неоднозначность обработай через [plan-first-communication](../plan-first-communication/SKILL.md).

Не клонируй клиент, стор, компонент или формулу ради удобного имени. Контракт ETL ведёт [data-contract](../data-contract/SKILL.md), интерфейс — [frontend-architecture](../frontend-architecture/SKILL.md).
