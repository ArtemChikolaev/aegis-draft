# Сохранения и постоянный прогресс

Найди фактических читателей/писателей в `web/src/state` и формат в соответствующем persist/store. Для серверного сейва дополнительно открой [backend-architecture](../backend-architecture/SKILL.md). Не создавай второй механизм persistence.

1. Раздели transient-забег, ограниченную историю результатов и постоянные достижения/награды. Постоянный unlock нельзя вычислять только из обрезаемой истории: старые победы будут забыты.
2. Для изменения формата определи старую версию, default/migration, поведение на повреждённом/будущем формате. Ошибка чтения не должна молча перезаписывать исходный сейв пустым.
3. Для забегов, зависящих от статического ETL-датасета, совместимость данных определяет `dataHash`, не `builtAt`. Не добавляй эту зависимость режиму без потребления ETL: [replay Аркады](../../../web/src/game/arcade/replay.ts) проверяет `ARCADE_CONFIG_VERSION`. Различай schemaVersion, ratingModelVersion, версию баланса режима и версию persistence; проследи реальную проверку, не бампать всё сразу.
4. Награду за завершение начисляй один раз по устойчивому идентификатору завершения. Повторный callback, reload, resume и повторный импорт не должны дублировать награду. Условие победы/полного акта берётся из engine, а не из анимации результата.
5. Сохрани текущую модель хранения и синхронизации; если запись состоит из нескольких шагов, проанализируй прерывание между ними. При изменении серверного протокола проверь конфликт и повторную доставку.
6. Проверь старый сейв, текущий round trip, повреждённые данные, повторное завершение и длинную историю за её лимитом. Для replay — воспроизведение на совместимой версии и явный отказ на несовместимой.

Локальные проверки делай на отдельном origin/фикстурах. Не очищай пользовательские localStorage/сейвы ради теста. Агентский dev-порт — 5273 по CLAUDE.md.

Выход: матрица совместимости до/после, правило начисления и результаты проверок. Смена фаз — [game-state-architecture](../game-state-architecture/SKILL.md).
