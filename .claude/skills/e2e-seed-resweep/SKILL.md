# Пересвип e2e-сидов anteRun.spec

Сценарии рогалита в [anteRun.spec.ts](../../../web/e2e/anteRun.spec.ts) доходят до Буткемпа и дальше только на «проходном» сиде: драфт «первым доступным» (`helpers.completeDraft`), исход этапа детерминирован по seed и пулу. Сдвиг пула — data-refresh, гейт присутствия, правила рынка или наград, ante-константы — делает сид непроходным, и тест падает **не** на регрессии кода. Лечится новым сидом, не ослаблением проверки. Сид обязан проходить на обоих датасетах: CI `web` гоняет mock, CI `web-e2e-real` — закоммиченный реальный.

## Когда
- Красный джоб «Web на реальном датасете (anteRun e2e + vitest)» при зелёном «Web (данные + логика + build)» — или наоборот.
- Тест не дошёл до сценария: висит на `ante-to-camp` / `camp-screen` / нужной карточке награды, а не на проверке UI.
- Красное впервые на коммите, где менялись только данные (бот data-refresh), пул, рынок, награды или ante-константы.

Не сюда: упало после правки экрана или селектора — это регрессия, чини код. Падает только в параллели или на mobile, а одиночным `-g "<имя>"` проходит — флейк. Golden — [self-review-checklist](../self-review-checklist/SKILL.md). Сиды Аркады и runLink от датасета не зависят.

## Карта сидов
| Сид в спеке | Тесты | Подбор (из `web/`) | Критерий |
|---|---|---|---|
| `CAMP_SEED` (env) | сценарии Буткемпа: этапы и завершение, пассивные карточки, resume, Playbook… | `npm run sim:sweep` → `CAMP ok` | 3 этапа с карточной наградой + static-смерть ≤6 этапов (бюджет `slow()`) |
| `CHEAT_SEED` (env) | cheat mode: boss на финале акта, поздние синки, trade-in, вне статистики | `npm run sim:sweep` → `CHEAT ok` | boost-модель доживает до финала акта + static-смерть ≤6; модель неточна — решает живой прогон |
| литерал теста разведки | «разведка раскрывает будущего босса» | `npm run sim:find-seed -- --scouting` | первая action-карта награды = scouting, этапы 1 и 2 пройдены |
| литерал теста stand-in | «stand-in делает замену игрока бесплатной» | `npm run sim:find-seed -- --stand-in` | этап 1 + первая action-карта = standIn |
| литерал теста предмета | «предмет в слоте показывает разложение силы» | `npm run sim:find-seed` | этап 1 + item-награда с нетривиальным разложением силы |

`find_camp_seed.ts` читает `MAX_SEED` (диапазон) и `MAX_FOUND`; для разведки годных сидов на реальном слайсе мало — расширяй диапазон. Новый захардкоженный сид в спеке — сразу режим подбора в finder.

## Процедура
Команды — из `web/`. В фоновой команде пиши `cd <абсолютный путь>/web &&` внутри неё самой: cwd фона сбрасывается, и `gen:mock`/playwright молча работают не там.

1. **Докажи дрейф.** Аннотации CI без `gh`: `https://api.github.com/repos/ArtemChikolaev/aegis-draft/actions/runs?per_page=20` → `…/actions/runs/<id>/jobs` → `…/check-runs/<job id>/annotations` (тест, строка, сводка Playwright). Найди первый красный прогон и что в нём поменялось. Прогони режим подбора по **текущему** сиду: не проходит критерий на этом датасете — дрейф. Finder считает сид годным, а живьём тест падает — репликация разошлась с тестом или это регрессия: разбирайся, не переподбирай.
2. **Кандидаты на реальном** — режим из карты.
3. **Кандидаты на моке** — `npm run gen:mock` (пишет в `web/.mock-data`), затем тот же режим с `AEGIS_DATA_DIR=.mock-data`. `gen:mock -- --out public/data` в рабочем дереве не запускать, данные через checkout/restore не возвращать.
4. **Пересечение с запасом.** Бери сид из пересечения с лучшим запасом: finder печатает места этапов, и «1 / 1» переживёт следующий refresh вероятнее, чем «7-8». Держи 2–3 запасных на случай живого провала.
5. **Живьём на реальном** — объём CI-джоба: `E2E_PORT=5274 npx playwright test e2e/anteRun.spec.ts --project=chromium`. `CAMP_SEED`/`CHEAT_SEED` подставляются через env без правки файла, литералы — правкой спеки. Порт должен быть свободен (`lsof -nP -iTCP:5274 -sTCP:LISTEN` пусто): локально `reuseExistingServer` молча подхватит чужой сервер с чужим деревом и данными.
6. **Живьём на моке** — оба проекта, в изолированной копии `web/`: на APFS `cp -c -R web "$TMPDIR/mockweb"` (клон вместе с node_modules за секунды; иначе отдельный worktree + `npm ci`); в копии `cp .mock-data/*.json public/data/` (наборы файлов совпадают: `diff <(ls public/data) <(ls .mock-data)`); там же `E2E_PORT=5275 npx playwright test e2e/anteRun.spec.ts`. Во время прогона `curl -s http://127.0.0.1:5275/data/manifest.json` показывает `mock dataset`. Копию после удали.
7. **Правка спеки.** Новый сид + строка комментария: дата, что сдвинуло пул, каким режимом подобран, запас. Проверки теста не ослаблять. Меняешь путь теста (новый клик, этап, карта) — тем же коммитом правь режим finder'а.
8. **Проверки и пуш.** `npm run typecheck` (scripts в него не входят: правил finder — прогони его режимы на обоих датасетах), `bash .claude/skills/self-review-checklist/tools/antipatterns_grep.sh` из корня, в `git status` нет `web/public/data`. Коммит и пуш по правилам проекта, затем дождись CI (`actions/runs?head_sha=<sha>`): зелёными должны стать оба web-джоба. Истёкший монитор — не зелёный CI.

## Грабли
- **Finder повторяет путь теста дословно:** `firstAvailableDraft` (не жадный драфт `sim_run`), первая карта нужного вида (как `helpers.chooseReward`), все этапы, которые проходит тест, свежая карьера (`setRarityFlags({ drops: false, upgrades: true })`, как у `gotoFreshApp`). Санити-проверка режима — он находит текущий зелёный сид на датасете, где тот проходит живьём; иначе ошибка репликации выглядит как «сид не подошёл».
- **`web-e2e-real` не входит в `needs` деплоя** намеренно: красный там не блокирует выкладку и легко висит днями. CI после data-refresh запускает бот, так что дрейф виден уже на коммите данных.
- **Локальная параллель флейкует на mobile** (`element is not stable`), а правка файлов во время прогона портит его через HMR. Сомнительное падение перепроверь одиночным `-g "<имя>"` или `--workers=1`.
- Порты: 5173 — пользователя, 5273 — агентский dev-сервер; e2e — 5274, мок-копия — 5275.

## Результат
Новый сид в спеке с комментарием; до пуша — зелёный живой `anteRun.spec` на реальном (chromium) и на моке (chromium + mobile); после пуша — зелёные оба web-джоба CI. В отчёте: что сдвинуло пул, пересечение, выбранный сид с запасом и запасные.
