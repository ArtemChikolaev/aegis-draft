# Косметика и спрайты Аркады

Для извлечения/рендера сначала прочитай [существующий пайплайн Dota](../../../docs/arcade-dota-sprites.md), [рендерер](../../../web/scripts/blender/render_dota_sprites.py) и нужный манифест в `web/scripts/blender`. Для регистрации — [cosmetics](../../../web/src/game/arcade/content/cosmetics.ts) и потребителей выбранного skin ID. Пути установленного Steam/Blender обнаруживай в среде, не считай личный путь разработчика переносимым.

1. Установи конкретного героя, сет, форму и дефект. Сохрани исходный результат для сравнения; проверь текущие изменения перед массовым перерендером.
2. Переиспользуй extractor/renderer и manifest. Сначала проверь один проблемный ассет; пакетную обработку запускай только после его проверки.
3. Проверь тело и wearable-части, привязку к скелету, материалы, варианты стиля, направления, анимации и особые формы. Не выводи соответствие персонажу только из имени файла.
4. Проведи автоматические проверки существующими `qa_*` скриптами из `web/scripts` по их поддерживаемым аргументам. Затем открой листы кадров и проверь ассет в игре: clipping, дрейф, пропавшие детали, силуэт, масштаб, переходы и прозрачность. Метрики и запись в manifest сами по себе не доказывают качество.
5. Проверь fallback при отсутствующем ассете, размер файлов и загрузку. Не подменяй глобально базовую модель ради одного сета. Косметика не должна менять hitbox, урон или RNG.
6. Сохраняй действующие правила доступности и атрибуцию; не вводи цену/анлок для ранее свободного сета без продуктового поручения. Не считать проектную заметку юридическим заключением о новых способах распространения.

7. Облик по слотам (T13.80): слои частей не рендерятся строками основного манифеста — только `dota_part_layers.mts plan → пайплайн с RAW=1 → build` (docs/arcade-dota-sprites.md §8); критерий — расхождение композита с образцом в выводе build и композит в гардеробе живьём. Слот части — из `dota_item_index.json` (item ID/`item_slot` из vpk, `dota_item_index.mts`), не по имени файла; модель без предмета — оверрайд с причиной в `dota_slot_overrides.json`. Аркана/стиль с другим телом — отдельное семейство (`--families`), не источник на базовом теле; у арканы со стилем рендери и семейство стиля (иначе смешанный облик теряет цвет — `styleDropped`); после новой семьи на теле арканы гоняй `qa_part_attach.mts` — слой, который «висит» (лук сета на аркане Drow: свой хват, refit-модели нет), закрепляй за основой в `dota_part_exclusions.json` с причиной, а не публикуй; идентичность строки `<hero>@arcana` проверяй по item ID арканы, а не по слову в пути. После переименования слоёв — `table` и миграция сейва (`migrateCosmeticsV*` в arcadeStore). Скин призыва — строка `<art>@<skin>` с `--hide-base`; проверь, что он анимирован (qa_sheet_health), а не застыл в bind-позе; если у скина свой скелет (волки Lycan) — рендери его основной моделью. Скин формы — строка `<hero>@meta~<имя>` (скелет базовой формы + `--hide-base`), слот косметики `form`; модель бери из `entityModels` индекса (подмена `hero_model_change`), не по имени папки.

Выход: перечень изменённых ассетов/манифестов, способ визуальной проверки и непроверенные формы. Игровые эффекты — [arcade-simulation](../arcade-simulation/SKILL.md), presentation — [game-feel-juice](../game-feel-juice/SKILL.md).
