# Режимы, фазы и состояние

Сначала найди актуальный стор и engine выбранного режима в `web/src/state` и `web/src/game`. Перечень режимов и этапов бери из кода; оркестрация уже существует, не создавай её заново по старому брифу.

- Mode shell (`selectedMode`) определяет выбранный режим независимо от конкретного забега.
- RunConfig содержит исполнимые опции соответствующего engine; не добавляй молча игнорируемые поля.
- Чистая логика в `game/` не импортирует UI или стор. Оркестрация этапов живёт поверх соответствующего engine; Аркада имеет собственные sim и store.
- UI-состояние перехода/анимации остаётся в presentation. Игровое ограничение реализуется там, где меняет правила, а не только скрытием кнопки.

## При изменении перехода

1. Опиши исходную фазу, действие и конечную фазу; найди все способы вызова, включая resume и повторный клик.
2. Reset очищает transient-состояние забега, сохраняя выбранный режим и постоянный прогресс.
3. Потеря незавершённого прогресса в игровом интерфейсе требует confirm. Отмена не меняет состояние. Это правило продукта, не запрос агентом разрешения на редактирование кода.
4. Новым сохраняемым полям нужны миграция/default на чтении и проверка старого сейва. После нормализации поле может быть обязательным; нельзя просто сделать его optional и оставить undefined в engine.
5. Проверь переход, отмену, повторный вызов и восстановление затронутой фазы. Для replay сохрани детерминизм seed + данные/контент + версия правил + действия.
