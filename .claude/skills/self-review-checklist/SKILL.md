# Self-review — пройди до того, как сказать «готово»

Прогон мысленно каждого изменённого файла. Один «да, проблема есть» → иди и почини.

## Когда применять
- Перед сообщением «готово, посмотри», перед коммитом/PR.
- После того как локально заработало (тут чаще всего пропускают ревью).

## Алгоритм
1. Автоскан: `bash .claude/skills/self-review-checklist/tools/antipatterns_grep.sh`.
2. Пройди чек-лист ниже мысленно по каждому файлу.
3. Diff-обзор: нет ли собственных несвязанных правок — убери только свои. Чужие изменения сохрани.
4. Статика/сборка:
   - Go: из затронутого модуля `pipeline/` или `server/`: `gofmt -l .` (пусто), `go vet ./...`, `go build ./...`, релевантные `go test`.
   - TS: из `web/` — `npm run typecheck`, релевантные тесты, при изменении UI/бандла build и затронутый живой сценарий.
   - Только docs/скиллы: ссылки, skill-validator и его тесты; сборка игры не нужна без изменения игрового кода.
5. Данные: менял `schema/` или data JSON → провалидируй (см. [data-contract](../data-contract/SKILL.md)) и синхронизируй оба конца.
6. Рейтинги: менял формулу → бампнул `ratingModelVersion` (см. [scoring-model](../scoring-model/SKILL.md)).
7. **Датасет vs golden.** CI web делает эфемерный `gen:mock` (тесты/golden); deploy — реальный `public/data` из data-refresh. Golden skip'аются без mock-baseline; после смены mock — `npm run test:golden:update`.
   - **Новый тест утверждает свойство РЕАЛЬНЫХ данных (доли, порядки, топы)? В CI он упадёт** — там мок с другими распределениями. Локально зелено, в CI красно. Оборачивай в `it.skipIf(isMockBaseline(...))` (`test/helpers/dataset.ts`) и пиши «(реальный датасет)» в имени, а инвариант, не зависящий от датасета (математика, полнота справочника), оставляй всегда включённым. Реальная шишка 2026-07-18: `elite` = 4.8% на реальных данных и ~30% на моке.
   - **Если изменение зависит от датасета, проверяй реальный и mock.** `gen:mock` запускай только в изолированной временной копии с текущими изменениями или CI checkout. В общем рабочем дереве он перезапишет данные. Не используй checkout/restore для возврата: можно уничтожить чужой датасет. Отсутствующий второй прогон явно укажи.
8. **Push ≠ deploy.** Если push поручен и выполнен, **дождись CI** и проверь **live**. Web: `validate:data && npm run test && npm run test:e2e && tsc && build`.
   - **Истёкший монитор — это НЕ зелёный CI.** Если следилка отвалилась по таймауту, сходи за статусом руками (`actions/runs?per_page=…`) и только потом говори «готово». Шишка 2026-07-18: три коммита подряд уехали с красным CI, потому что мониторы истекли, а я на них положился.

## Категории проверки
### Reuse / архитектура
- Написал новое, хотя есть готовое (см. [discovery-before-code](../discovery-before-code/SKILL.md))? → переиспользуй.
- Границы: Go `internal/*` стадии не лезут друг в друга через глобалы; TS `game/` (логика) не зависит от `ui/`; доступ к данным — через `DataSource`, не прямой fetch по компонентам.
- Секреты (ключ OpenDota, контакт UA) не в коде, а в env.

### UI / design-system (если трогал `web/src/ui|features|app|design`, см. [frontend-architecture](../frontend-architecture/SKILL.md))
- Новый UI-элемент собран из примитивов `ui/` (или добавлен variant), а не bespoke `<div>` со стилями.
- **Ноль хардкод-цветов** (`#hex`, `rgba`) в компонентах/tsx — только токены `design/tokens.css`; нового `html[data-theme=…]`-override нет (значит цвет токенизирован).
- Весь видимый текст — ключ `i18n/core.ts` (RU + EN синхронно), не хардкод-строка. Примитивы `ui/` презентационные (i18n снаружи).
- Экран — в `features/`, примитив — в `ui/` (не наоборот). Проверил light + dark вживую.

### Контракт данных
- Тронул формат статических ETL-данных, не тронув `schema/` → рассинхрон. `steamId64` допустим только как raw-вход в `pipeline/internal/normalize`; после normalize и во всех output — единый `accountId`.
- Ручные ETL-типы `web/src/types/data.ts` не синхронизированы со схемой (генератора сейчас нет).
- **`web/public/data` в diff — почти всегда ошибка.** `npm run gen:mock` пишет в ТОТ ЖЕ каталог, где
  лежит боевой датасет: прогнал мок для проверки UI — и в коммит уезжают 22 пака вместо 1415. На
  глаз в diff это не видно, файлы те же, меняются только числа внутри (грабля 2026-08-05, поймана
  дважды подряд). Датасет собирает только CI (`data-refresh`), руками его не коммитят. Проверка
  автоматизирована в `antipatterns_grep.sh`. Не откатывай данные вслепую: сначала установи происхождение изменений и восстанови только свой побочный результат из заранее сохранённой копии.

### Дубликаты / мёртвый код
- Две функции отличаются на 1 строку → параметризуй.
- Скопированный кусок между `pipeline`/`web` → общий модуль/справочник.
- Закомментированный код, `fmt.Println`/`console.log`-отладка, TODO без owner → убрать.
- Неиспользуемые импорты/переменные/экспорты.

### Скоринг
- Сырой winrate при малых выборках (нет сглаживания/порога).
- Жадное назначение героев вместо matching.
- Роли поделены на 4/5 (запрещено, PRD §5.1).

### Edge cases
- Пустой пул паков по формату; игрок без hero-stats; пара без squadSynergy; окно Peak без `N_min` игр; бесконечные рерроллы (Easy) не ломают состояние.
